# 广告落地页回流（Return Page）实现：返回键接管、切后台重访与防打扰状态机

> 一句话结论：买来的冷流量有 60%–80% 不会在第一次滑完页面时就开口或提交表单。**做好落地页回流（Return Page / Back-Button Retention）的本质，是在用户「点手机返回键」或「切去别的 App 又切回来」的那一秒，用换了角度的第二版内容做一次温柔的二次承接**——既不能死循环锁死返回键惹毛用户，也不能对已经成单的人重复弹窗。

很多外包落地页写「返回拦截」时，直接用一个 `while` 循环或无限制的 `history.pushState` 把浏览器返回键锁死——用户连按五次返回都退不出去，结果就是直接投诉广告，导致广告账户评分暴跌。

真正工程化、合规可控的回流系统必须同时解决三个问题：

1. **怎么准确感知「用户准备走」或「刚从外部切回来」？**
2. **接住之后给用户看什么？（单卡弹窗 `Popup` vs. 整屏信息流 `Feed`）**
3. **什么时候必须闭嘴？（同会话只触发一次 + 已点过主 CTA 自动静默）**

下面把完整状态机、伪代码与可直接嵌入页面的零依赖实现拆开写清。

## 一、三类回流触发信号（为什么不能只监听 `popstate`）

在移动端投流场景里，用户的离开与复访主要有三种动作，对应三个浏览器原生事件：

```text
访客进入落地页 (记录 enteredAt, 初始查询串 utm_*/fbclid)
        │
        ├──► 信号 1：点手机左滑返回 / 顶部返回键 (window "popstate")
        │       前提：页面发生过首次有效交互（scroll / pointerdown）后压入 1 个哨兵 state
        │       动作：消耗掉这个哨兵 state，展示回流层；用户若再按一次返回，立刻放行退出！
        │
        ├──► 信号 2：切去聊天软件/后台超过 N 秒后切回当前标签页 (document "visibilitychange")
        │       前提：hidden 持续时长 >= minAwaySeconds（如 8 秒），排除瞬时误触锁屏
        │       动作：回到 visible 时触发回流欢迎层，帮用户接回刚才中断的动作
        │
        └──► 信号 3：桌面端鼠标快速移向浏览器顶部关闭栏 (document "mouseleave", clientY <= 0)
                前提：停留时长 >= minDwellMs（如 3000ms）
                动作：触发桌面端挽留层
```

为什么信号 1 强调**「最多只压 1 个哨兵历史栈，且触发后不再重压」**？

因为 Chrome 和 Safari 有「History Manipulation Intervention（历史记录操纵干预）」机制：如果一个页面在无用户手势时疯狂 `pushState`，或者在 `popstate` 回调里再次 `pushState` 阻止退出，浏览器会直接跳过你的记录，甚至把域名标为恶意体验。**只拦截第一次返回、第二次返回无条件放行**，是体验与转化的黄金平衡点。

## 二、两种回流承接形态：`Popup`（页面级弹窗）vs. `Feed`（整屏信息流）

同一个用户之所以点返回，往往是因为当前页面第一屏的角度没打中他。这时候如果只弹一个写着「别走！」的简陋框，意义不大。生产实践中通常分两种形态：

| 维度 | 形态 A：页面级回流弹窗 (`format = "popup"`) | 形态 B：整屏信息流回流页 (`format = "feed"`) |
|---|---|---|
| **视觉形态** | 半透明遮罩 + 居中/底部卡片（带竖版封面图或短片、简短钩子、单按钮） | 无缝替换或全屏覆盖为类似「精选内容流 / 短剧推荐集 / 常见问题卡片流」的多卡片列表 |
| **心理机制** | 降低决策门槛（例如从「直接填长表单」降级为「先加客服拿一份资料表」） | 承接「还想再逛逛」的浏览惯性——用户以为退回了信息流，其实还在你的转化漏斗里 |
| **适合品类** | 单品 COD、B2B 留资、明确的单一服务咨询 | 短剧/小说、多款式商品超市、应用下载、多主题内容咨询 |
| **参数要求** | 主 CTA 自动继承当前页的 `utm_*` 与 `fbclid`/`ttclid` | 信息流里每一张卡片的 CTA 都必须自动透传原页面的 `utm_*` 与点击归因 ID |

## 三、防打扰铁律：回流状态机伪代码

为了让回流层既能捞回流失访客，又不污染正常转化链路，状态机必须内置**四道阀门**：

```text
state = {
    enteredAtMs: now(),
    hiddenAtMs: null,
    hasUserInteracted: false,
    hasConverted: false,          # 用户一旦点过主 CTA 或提交过表单，立刻置为 true
    firedCountInSession: sessionStorage.get("ret_fired") ?? 0
}

function canFireRetention(triggerType, config):
    # 阀门 1：已经发生过主转化（点过客服按钮或填过单）的人，绝对不再弹窗打扰
    if config.suppressAfterConversion and state.hasConverted:
        return { allow: false, reason: "already_converted" }

    # 阀门 2：同一会话只触发 1 次（防反复骚扰）
    if config.oncePerSession and state.firedCountInSession >= 1:
        return { allow: false, reason: "session_limit_reached" }

    # 阀门 3：进站停留未满最小阈值（如 3 秒），说明是误点，不强留
    dwellMs = now() - state.enteredAtMs
    if dwellMs < config.minDwellMs:
        return { allow: false, reason: "dwell_too_short" }

    # 阀门 4：如果是切后台重访，离开时长必须达到设定秒数（如 8 秒）
    if triggerType == "revisit":
        awaySec = (now() - state.hiddenAtMs) / 1000
        if awaySec < config.minAwaySeconds:
            return { allow: false, reason: "away_too_short" }

    return { allow: true, reason: "ok" }
```

## 四、零依赖前端实现（约 70 行，可直接内联到落地页）

下面这段控制器同时实现了：首次交互后挂载单次返回哨兵、切后台超时重访检测、主 CTA 转化自动静默、以及 UTM 参数向回流卡片的无损透传：

```js
/**
 * 落地页回流二次承接控制器（Popup / Feed 通用，单会话仅触发 1 次）
 */
export function initReturnRetention(config = {}) {
  const opts = {
    trigger: config.trigger || 'both',          // 'back' | 'revisit' | 'both'
    format: config.format || 'popup',           // 'popup' | 'feed'
    minDwellMs: config.minDwellMs ?? 3000,
    minAwaySeconds: config.minAwaySeconds ?? 8,
    storageKey: config.storageKey || '__lp_ret_fired_v1',
    onShow: config.onShow || function () {}
  };

  const state = {
    enteredAt: Date.now(),
    hiddenAt: 0,
    armedBackHistory: false,
    converted: false,
    fired: sessionStorage.getItem(opts.storageKey) === '1'
  };

  function tryFire(source) {
    if (state.fired || state.converted) return false;
    if (Date.now() - state.enteredAt < opts.minDwellMs) return false;

    state.fired = true;
    try { sessionStorage.setItem(opts.storageKey, '1'); } catch (_) {}
    opts.onShow({ source, format: opts.format, search: location.search });
    return true;
  }

  // 1. 监听页面内所有主转化动作：一旦用户主动点过主 CTA 或提交表单，自动静默回流层
  document.addEventListener('click', (e) => {
    const cta = e.target.closest('[data-primary-cta], form button[type="submit"]');
    if (cta) state.converted = true;
  }, true);

  // 2. 返回键接管：等用户发生首次真实交互后再压入 1 个哨兵历史记录
  if (opts.trigger === 'back' || opts.trigger === 'both') {
    const armOnce = () => {
      if (state.armedBackHistory || state.fired) return;
      state.armedBackHistory = true;
      try {
        history.pushState({ __lpRetentionGuard: 1 }, '', location.href);
      } catch (_) {}
    };
    window.addEventListener('pointerdown', armOnce, { once: true, passive: true });
    window.addEventListener('scroll', armOnce, { once: true, passive: true });

    window.addEventListener('popstate', () => {
      tryFire('back_button');
    });
  }

  // 3. 切后台重访接管：离开超过 minAwaySeconds 秒再切回时触发
  if (opts.trigger === 'revisit' || opts.trigger === 'both') {
    document.addEventListener('visibilitychange', () => {
      if (document.visibilityState === 'hidden') {
        state.hiddenAt = Date.now();
      } else if (document.visibilityState === 'visible' && state.hiddenAt > 0) {
        const awaySec = (Date.now() - state.hiddenAt) / 1000;
        state.hiddenAt = 0;
        if (awaySec >= opts.minAwaySeconds) {
          tryFire('tab_revisit');
        }
      }
    });
  }

  return {
    markConverted() { state.converted = true; },
    getState() { return { ...state }; }
  };
}
```

## 五、回流页与 PWA 怎么配合用（双层留存漏斗）

回流页和 PWA 桌面图标刚好覆盖了冷流量的两个不同阶段：

1. **当次会话挽留（回流页管「现在别白走」）**：用户第一次点进来没看懂主落地页、手滑点返回时，弹出回流弹窗或切到信息流回流页，换一个更轻的入口（比如领一份试用表、看另一集短剧、或把应用加到主屏幕）。
2. **跨天复访留存（PWA 管「以后找得到」）**：对于愿意留下的用户，引导一键添加到手机主屏幕，把一次性买量变成桌面上的常驻图标，后续每次从桌面打开都是零广告费的自然复访。

## 六、上线前自检清单

- [ ] **连按两次返回键能正常退出**：第 1 次点返回弹出回流层，第 2 次再点返回必须顺畅退回上一页，绝不死锁。
- [ ] **点过主按钮后不再弹窗**：先点一下页面上的主咨询按钮，再按返回或切后台回来，确认回流层已自动静默。
- [ ] **参数完整继承**：回流弹窗或信息流卡片上的按钮，点出去依然带着首次进站时的 `utm_source`、`utm_campaign` 与 `fbclid`/`ttclid`。
- [ ] **统计独立拆分**：回流层的展示（`return_impression`）与回流点击（`return_cta_click`）与主页面的首屏点击分开记录，方便复盘回流到底救回了多少比例的线索。
