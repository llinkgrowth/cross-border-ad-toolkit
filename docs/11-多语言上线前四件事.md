# 多语言落地页上线前先查这 4 件事：方向、数字、按钮、参数

> 一句话结论：多语言落地页翻完只是开始。上线前只查四件事——书写方向对不对、数字会不会被输入法写成另一种、按钮会不会被长译文撑破、切语言时广告参数还在不在。

很多团队的顺序是反的：先生成 10 个语言版本，再投。投出去才发现阿拉伯语整页没镜像、手机号框不认另一套数字、西班牙语按钮换了两行、用户一切语言点击编号就没了。返工比一开始多写 40 行校验贵得多。

下面四项都可以用纯函数在发布前跑完，不依赖翻译服务。

## 一、方向：不是只翻文字

阿拉伯语、希伯来语、波斯语、乌尔都语要从右往左读。只把句子翻过去、布局仍从左往右，价格和按钮会看起来像另一个页面。

判断标准：根节点同时有 `lang` 和 `dir`。图标和箭头跟文字一起镜像，不要只翻文案。

```text
function layoutFor(locale):
    rtl = locale in { ar, he, fa, ur }
    return { dir: rtl ? "rtl" : "ltr", mirrorIcons: rtl }
```

不合格怎么改：CSS 用 `margin-inline`、`padding-inline`、`text-align: start`，不要写死 `margin-left`。

## 二、数字：输入法会写出另一套数字

阿拉伯语键盘默认可能打出另一套数码。正则如果只认 `0-9`，这批真实访客会全部卡在手机号校验上。

提交前先把那一套数码归一成 ASCII，再校验长度。日期和货币符号的位置也要按语言包来，不要把同一种金额写法原样贴进所有语言。

## 三、按钮：译文比英语长 40% 就要报警

西班牙语、德语、葡萄牙语的动词短语经常比英语长三到五成。首屏主按钮一旦换行，手机上的第一眼就断了。

```text
function buttonOverflow(english, translated):
    if length(english) < 4: return ok
    if length(translated) / length(english) > 1.4: return warn
    return ok
```

太短的词不做比例对比，避免误报。报警之后改的是按钮宽度或缩短译文，不是关掉检查。

## 四、参数：切语言不能把广告点击编号弄丢

语言切换如果写成死链，入口上的来源参数和点击编号会全部消失。广告后台就会显示有点击、没转化。

正确做法只改语言标记，其余查询参数原样保留：

```text
function switchLocale(currentSearch, nextLocale):
    params = parse(currentSearch)
    params.set("lang", nextLocale)
    return "?" + params
```

从广告链接进来，切一次语言，再看地址栏：点击编号还在，才算过关。
