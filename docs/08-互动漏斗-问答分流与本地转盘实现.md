# 把冷流量变成主动咨询：问答漏斗（Quiz Funnel）与本地转盘状态机实现

> 一句话结论：冷流量刚从短视频广告点进来时，信任度是零——首屏直接放 5 个输入框要电话，85% 的人会直接划走。**互动问答落地页（Quiz / StepFlow Funnel）用 3 个低门槛选择题制造「微承诺（Micro-commitment）」，再按答案标签自动分流到不同接待组，并把用户的回答直接塞进咨询首句**，不仅留存率高，客服开口就能精准接话。

在跨境咨询（护肤定制、减重方案、法律/税务评估、B2B 选型、教育培训）与活动电商里，最高效的页面形态早已不是「一张长图到底」，而是**交互式分支漏斗**。

但很多团队把问答和转盘做成了纯花架子：用户点完 3 道题，跳出去的链接还是同一个通用客服号，客服上来还得重新问一遍「您是什么情况？」；或者转盘没有本地幂等锁，用户刷新五次页面抽五次奖，一眼看穿是假组件。

下面把**多步问答计分与标签路由算法**、**浏览器本地确定性转盘 + 发布门禁校验**、以及**App 内置浏览器跳出辅助（External Browser Handoff）**的核心伪代码与实现拆开写清。

## 一、多步问答分支路由状态机（Quiz / StepFlow）

一个标准的 3 步问答漏斗做三件事：

1. **降低首屏动作阻力**：第 1 屏不谈钱、不要电话，只问一个用户最关心且 1 秒能点选的问题（如「你目前最困扰的皮肤问题是？」）。
2. **给访客打人群标签（Scoring & Tagging）**：根据 3 道题的选项累加分值（`score`）或标签集合（`tags`），在最后一屏匹配出最合适的方案与接待通道（例如预算充足的高意向客户分给金牌顾问组，价格敏感型客户分给自助领券页）。
3. **把答案摘要拼进客服预填首句**：用户点最后一步的「获取我的专属方案」跳去 WhatsApp 或 Telegram 时，输入框里已经自动填好了他的 3 个答案摘要。

### 路由与首句拼装伪代码

```text
function evaluateQuizFunnel(questions, userAnswers, routingRules, pageSearch):
    totalScore = 0
    collectedTags = []
    summaryPairs = []

    # 1. 遍历用户回答，累加分值、收集标签、生成可读摘要
    for q in questions:
        chosenOptionId = userAnswers[q.id]
        opt = findOption(q.options, chosenOptionId)
        if opt is null:
            return { ok: false, error: "MISSING_ANSWER:" + q.id }

        totalScore = totalScore + (opt.score ?? 0)
        collectedTags.appendAll(opt.tags ?? [])
        summaryPairs.append(q.shortKey + "=" + opt.shortValue)

    # 2. 按优先级匹配路由规则（按必含标签或最低分值）
    matchedRoute = defaultRoute
    for rule in routingRules:
        if totalScore >= rule.minScore and containsAll(collectedTags, rule.requiredTags):
            matchedRoute = rule
            break

    # 3. 拼装带答案摘要与渠道归因标记的预填首句
    # 示例: "Hello, I finished the assessment [Quiz: Goal=Hydration | Skin=Dry] [src:tiktok]"
    quizSummary = "[Quiz: " + join(summaryPairs, " | ") + "]"
    utmSource = parseQueryParam(pageSearch, "utm_source")
    sourceTag = "[src:" + utmSource + "]" if utmSource else ""
    prefilledText = trim(matchedRoute.greetingTemplate + " " + quizSummary + " " + sourceTag)

    # 4. 生成最终目标链接并透传原页面的 utm_* / fbclid / ttclid
    finalUrl = buildDestinationUrl(matchedRoute.targetUrl, prefilledText, pageSearch)

    return {
        ok: true,
        totalScore,
        tags: unique(collectedTags),
        tierId: matchedRoute.id,
        prefilledText,
        finalUrl
    }
```

这样客服收到消息的第一秒，看到的不是一句冷冰冰的 `"Hi"`，而是：

```text
Hi, I'd like to get my plan [Quiz: Type=B2B | Team=10-50 | Urgency=ThisWeek] [src:facebook]
```

不用多问三句废话，直接进入有效沟通。

## 二、浏览器本地活动转盘：加权抽取 + 防刷幂等锁 + 发布门禁

在活动型落地页里，转盘（PrizeWheel）用来发本地体验券或引导加客服领福利。要让组件显得真实可信、且上线不翻车，工程上必须守住三条线：

1. **发布门禁校验（`validateWheelConfig`）**：任何权重大于 0 的中奖扇区，**必须绑定一个有效的下一步动作（跳转客服链接或展开留资表单）**——否则用户转中了却没地方兑奖，这页广告费就白烧了。
2. **同设备持久化锁定（`localStorage` 幂等）**：同一个访客转过一次之后，把抽中的扇区 ID、生成的本地兑换码和旋转角度存进 `localStorage`；**用户刷新页面再进来，转盘直接停在刚才抽中的位置并展示兑换按钮**，不能无限重转。
3. **无服务端伪造承诺**：本地转盘只做活动互动与发放公开体验码，不宣称「实时全网限量库存台账」，也不写绝对化收益承诺。

### 加权抽取与旋转角度计算（纯函数实现）

```js
/**
 * 校验转盘配置是否满足上线门禁
 */
export function validateWheelConfig(sectors = []) {
  const errors = [];
  if (!Array.isArray(sectors) || sectors.length < 2) {
    errors.push('转盘至少需要配置 2 个扇区');
    return { valid: false, errors };
  }
  let totalWeight = 0;
  for (const s of sectors) {
    const w = Number(s.weight ?? 0);
    if (w < 0 || !Number.isFinite(w)) {
      errors.push(`扇区 ${s.id} 权重不合法`);
    }
    totalWeight += w;
    if (w > 0 && !s.isEmptyPrize && (!s.ctaUrl || !String(s.ctaUrl).trim())) {
      errors.push(`可命中的奖励扇区「${s.label || s.id}」未绑定下一步 CTA 动作链接`);
    }
  }
  if (totalWeight <= 0) {
    errors.push('所有扇区总权重必须大于 0');
  }
  return { valid: errors.length === 0, totalWeight, errors };
}

/**
 * 按权重抽取扇区并计算最终旋转角度（默认先转满 5 圈 = 1800 度，再精准停在目标扇区中心）
 */
export function spinPrizeWheel(sectors, randomFloat = Math.random(), minFullSpins = 5) {
  const check = validateWheelConfig(sectors);
  if (!check.valid) {
    throw new Error(check.errors.join('; '));
  }

  let threshold = randomFloat * check.totalWeight;
  let winnerIndex = sectors.length - 1;
  for (let i = 0; i < sectors.length; i++) {
    threshold -= Number(sectors[i].weight);
    if (threshold <= 0) {
      winnerIndex = i;
      break;
    }
  }

  const sectorAngle = 360 / sectors.length;
  // 让指针停在目标扇区的正中间（顺时针旋转补偿）
  const targetCenterDeg = 360 - (winnerIndex * sectorAngle + sectorAngle / 2);
  const rotationDeg = minFullSpins * 360 + Math.round(targetCenterDeg * 100) / 100;

  return {
    winnerIndex,
    sector: sectors[winnerIndex],
    rotationDeg
  };
}
```

## 三、App 内置浏览器跳出辅助（解决 WebView 里唤不起外部软件）

当用户在 Facebook、Instagram 或 TikTok App 内部点击广告时，页面是在 App 自带的内置浏览器（In-App WebView）里打开的。

内置浏览器有两个常见痛点：
- 点击 `wa.me` 或自定义协议链接时，部分机型偶发白屏或拦截，无法顺畅唤起手机里的 WhatsApp 客户端；
- 内置浏览器不共享用户平时在 Chrome / Safari 里的登录态，且不支持安装桌面 PWA。

工程上的处理方式是**在点击 CTA 前检测内置浏览器 UA，按 Android 与 iOS 分支给出最佳跳出辅助**：

```js
export function buildExternalBrowserHandoff(targetUrl, userAgent = '') {
  const ua = String(userAgent);
  const inAppMatch = ua.match(/(FBAN|FBAV|Instagram|BytedanceWebview|TikTok|Line\/|Snapchat)/i);
  const isInApp = Boolean(inAppMatch);
  const isAndroid = /Android/i.test(ua);
  const isIOS = /(iPhone|iPad|iPod)/i.test(ua);

  if (!isInApp) {
    return {
      isInApp: false,
      appName: null,
      strategy: 'direct_navigation',
      handoffUrl: targetUrl
    };
  }

  // Android 内置浏览器：可构造 intent:// 尝试唤起系统默认 Chrome 打开目标地址
  if (isAndroid && /^https?:\/\//i.test(targetUrl)) {
    const stripped = targetUrl.replace(/^https?:\/\//i, '');
    const scheme = targetUrl.startsWith('https') ? 'https' : 'http';
    const intentUrl = `intent://${stripped}#Intent;scheme=${scheme};action=android.intent.action.VIEW;end`;
    return {
      isInApp: true,
      appName: inAppMatch[1],
      strategy: 'android_intent_wakeup',
      handoffUrl: intentUrl,
      fallbackUrl: targetUrl
    };
  }

  // iOS 内置浏览器：如果目标是 wa.me/...，直接走 Universal Link；若需跳系统 Safari 则展示右上角指引
  return {
    isInApp: true,
    appName: inAppMatch[1],
    strategy: isIOS ? 'ios_universal_or_guide' : 'fallback_direct',
    handoffUrl: targetUrl
  };
}
```

> 边界诚实说明：是否允许从内置 WebView 跳出到系统浏览器，最终取决于手机操作系统与宿主 App 当前版本的策略，前端 `intent://` 只能提高唤起成功率，**不能在文案里承诺「100% 强制跳出」**，并且必须保留 `fallbackUrl` 原链接兜底。

## 四、上线前自检清单

- [ ] **问答每一步都有进度感**：顶部显示 `Step 1 of 3`（33% → 66% → 100%），每道题选项不超过 4 个，单手大拇指可点。
- [ ] **答案摘要已塞进首句**：点完最后一步跳去 WhatsApp，检查聊天输入框里是否已经带上了 `[Quiz: ...]` 摘要。
- [ ] **转盘刷新不重置**：抽完一次奖后刷新浏览器，确认转盘保持已开奖状态、显示同一个兑换码，不会变成无限重抽。
- [ ] **所有中奖扇区都有 CTA**：用 `validateWheelConfig` 跑一遍配置，确认没有「抽中了却点不动」的死胡同扇区。
