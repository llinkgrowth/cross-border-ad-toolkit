# 广告像素事件与去重规范：Meta / TikTok / GA4 对照表与校验伪代码

> 一句话结论：做好**广告像素配置**的核心不是多装代码，而是避免**事件名拼错、同一脚本装了两遍、跳转把 `fbclid`/`ttclid` 冲掉了、或者浏览器与回传没有共用同一个 `event_id`**。

投手每天最头疼的对账场景是：后台明明进了 30 个表单或订单，广告管理器里要么显示 0，要么显示 68。前者让广告计划过不了学习期，后者把单次转化成本算成假低、预算越加越亏。

下面把「三平台标准事件字典」「确定性 `event_id` 去重算法」「点击归因 ID 捕获」和「上线前静态校验伪代码」一次写清。

---

## 一、三平台标准事件对照表（别自己发明事件名）

广告平台的优化模型只认它的**标准事件名（Standard Events）**。很多外包页面在按钮上写 `fbq('track', 'whatsapp_click')`——这会被当成自定义事件，新建广告组时根本选不到标准优化目标。

| 统一业务动作 | 触发时机 | Meta Pixel (`fbq`) | TikTok Pixel (`ttq`) | Google Analytics 4 (`gtag`) | 必填/强建议参数 |
|---|---|---|---|---|---|
| `page_view` | 页面首屏加载完成 | `PageView` | `PageView` | `page_view` | — |
| `view_content` | 浏览商品/核心详情 | `ViewContent` | `ViewContent` | `view_item` | `content_ids`, `content_type` |
| `contact` | 点击 WhatsApp/TG 咨询按钮 | `Contact` | `Contact` | `generate_lead` | `content_name` |
| `lead` | 留资表单提交成功 | `Lead` | `SubmitForm` | `generate_lead` | `value`, `currency`（可选） |
| `add_to_cart` | 选中规格/加入购物车 | `AddToCart` | `AddToCart` | `add_to_cart` | `value`, `currency`, `contents` |
| `initiate_checkout` | 展开/进入结账表单 | `InitiateCheckout` | `InitiateCheckout` | `begin_checkout` | `value`, `currency` |
| `purchase` | 订单提交成功（含 COD） | `Purchase` | `CompletePayment` | `purchase` | **`value`（数字）, `currency`（3 位 ISO）** |
| `complete_registration` | 完成注册/预约 | `CompleteRegistration` | `CompleteRegistration` | `sign_up` | `status` |

三条硬规矩：

1. **大小写敏感**：Meta 的 `InitiateCheckout` 写成 `initiate_checkout` 就是错；GA4 反过来全用小写下划线 `begin_checkout`。
2. **`Purchase` / `CompletePayment` 必须带合法 `value` 和 3 位 ISO `currency`**：传 `"$49.9"`（带符号字符串）或 `"USDT"`（非 ISO 4217 法币码）都会在平台诊断里报错。
3. **在「动作完成时」触发，不在「页面加载时」触发**：把 `Lead` 写在落地页 `<head>` 里，等于每个点进来的访客都算成转化，广告模型三天就会跑偏。

## 二、去重核心：确定性 `event_id` 怎么生成

当同一笔转化可能被触发多次（例如用户双点提交按钮、刷新感谢页、或者前端像素与后端回传同时上报）时，平台靠 `event_id` 去重：**48 小时内收到相同 `event_names` + 相同 `event_id`，只记一次**。

如果两边各自 `Math.random()` 生成一个 UUID，去重就完全失效。正确做法是用**业务键生成确定性 ID**：

```text
function generateEventId(pageSlug, action, visitorSeed, orderOrLeadId, timestampMs):
    # 如果有明确的订单号/线索 ID，直接用它做幂等键（刷新感谢页也不会变）
    if orderOrLeadId is not empty:
        rawKey = pageSlug + ":" + action + ":order:" + orderOrLeadId
    else:
        # 按钮点击类事件（如 Contact）：按 10 秒时间桶去重，防连点两下算两次
        bucket = floor(timestampMs / 10000)
        rawKey = pageSlug + ":" + action + ":visitor:" + visitorSeed + ":t:" + bucket

    return "evt_" + fnv1aHex(rawKey)
```

调用方式对照：

```js
// 1. Meta Pixel 带 eventID（注意第 4 个参数结构）
fbq('track', 'Purchase', { value: 49.00, currency: 'USD' }, { eventID: eventId });

// 2. TikTok Pixel 带 event_id
ttq.track('CompletePayment', { value: 49.00, currency: 'USD' }, { event_id: eventId });

// 3. GA4 带 transaction_id
gtag('event', 'purchase', { transaction_id: eventId, value: 49.00, currency: 'USD' });
```

## 三、点击归因 ID（`fbclid` / `ttclid` / `gclid`）为什么会丢

用户从广告点进来时，URL 上带着平台生成的点击 ID：

```text
?utm_source=facebook&utm_medium=cpc&fbclid=IwAR0x9y8z7...
```

最常见的三种丢失原因：

1. **短链 302 跳转没透传查询串**：短链只跳去了固定的 `/landing`，把入口的 `?fbclid=...` 扔了。
2. **页面内语言切换或二次跳转**：用户点「切换阿拉伯语」跳到 `/ar/index.html`，链接写死了不带 `location.search`。
3. **还没等像素请求发出去就立刻 `location.href` 跳走了**：在 WhatsApp 按钮的 `onclick` 里同步调用 `fbq('track', 'Contact')` 然后紧接着 `location.href = 'wa.me/...'`，移动端浏览器会直接中止尚未完成的网络请求。

修复代码（首屏落盘 + 延迟 180ms 跳转）：

```js
// 1. 首屏加载时立刻把点击 ID 写入 sessionStorage，防页内跳转丢失
(function persistClickIds() {
  const params = new URLSearchParams(location.search);
  const saved = JSON.parse(sessionStorage.getItem('__ad_click_ids') || '{}');
  for (const key of ['fbclid', 'ttclid', 'gclid', 'gbraid', 'wbraid', 'utm_source', 'utm_campaign']) {
    if (params.get(key)) saved[key] = params.get(key);
  }
  sessionStorage.setItem('__ad_click_ids', JSON.stringify(saved));
})();

// 2. 外跳按钮：先发事件，等 180ms 或用 Beacon，再跳转
function trackAndRedirect(targetUrl, firePixelFn) {
  try { firePixelFn(); } catch (_) {}
  setTimeout(function () {
    location.href = targetUrl;
  }, 180);
}
```

## 四、上线前静态校验器（伪代码）

与其等投出去烧了钱才发现没数，不如在发布前对 HTML 和事件 Payload 跑一遍静态检查：

```text
function lintLandingPagePixels(htmlString):
    issues = []

    # 1. 检查同一平台的 base script 是否被注入了多次（最常见的「转化翻倍」元凶）
    if countMatches(htmlString, "connect.facebook.net") > 1:
        issues.push(FAIL("DUPLICATE_FB_SDK", "fbevents.js 被加载了多次，每个事件会重复上报"))
    if countMatches(htmlString, "analytics.tiktok.com") > 1:
        issues.push(FAIL("DUPLICATE_TT_SDK", "TikTok 像素基础脚本重复加载"))

    # 2. 检查是否在首屏同步直发转化事件
    if matches(htmlString, "fbq('track', 'Lead')") or matches(htmlString, "fbq('track', 'Purchase')"):
        if not insideEventHandler(htmlString):
            issues.push(WARN("INLINE_CONVERSION_ON_LOAD", "检测到转化事件可能在页面加载时直接触发，请确认是否绑定在按钮或表单成功回调中"))

    # 3. 检查常见事件名拼写错误
    for typo in ["init_checkout", "add_cart", "submit_lead", "whatsapp_click"]:
        if contains(htmlString, typo):
            issues.push(FAIL("NON_STANDARD_EVENT", "非标准事件名: " + typo))

    return issues
```

## 五、5 分钟排查清单

- [ ] `<head>` 里每个平台的像素初始化代码只有 **1 份**（没有头尾各贴一次）。
- [ ] `PageView` 随页面加载触发；`Contact` / `Lead` / `Purchase` **只在用户点击或提交成功回调里触发**。
- [ ] 交易类事件的 `value` 是纯数字（如 `49.9`），`currency` 是 3 位大写字母（如 `USD`、`SAR`、`BRL`）。
- [ ] 外跳 WhatsApp / Telegram 按钮留了 150–200ms 缓冲时间，没有立刻打断像素请求。
- [ ] 每次触发都带上了确定性的 `eventID` / `event_id`。
