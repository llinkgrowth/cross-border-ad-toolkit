# 多语言落地页：难的不是翻译，是这 3 件事

> 一句话结论：多语言落地页的难点不在「翻成几种语言」，而在「翻完之后页面还能不能用、数据还算不算得清」。

很多团队做多语言页面的顺序是反的：先找翻译，把中文文案丢进翻译工具，生成几页英文、阿语、泰语，然后上线。上线后发现问题不在翻译质量——按钮被撑破、价格小数点错位、广告后台的转化数对不上。返工的成本，比一开始就按语言做三版还高。

下面三件事，是上线前必须过的关。

## 一、字体与排版：翻完只是开始，版面会崩

同一个页面，中文里一行放得下的按钮文字，德语可能长出 40%；阿拉伯语是从右往左读，整个布局要镜像；泰语和越南语的变音符号会改变行高；阿拉伯语和希伯来语里的数字方向，会让价格看起来像另一个数。

这不是设计问题，是排版规则问题。判断标准很简单：**把页面语言逐个切过去，不看翻译，只看三处——按钮有没有被撑破、价格和数字有没有错位、表单标签有没有被截断。**

不合格怎么改：

- 阿拉伯语、希伯来语：整个页面 `dir="rtl"`，图标和箭头一起镜像，不要只翻文字。
- 德语、俄语：按钮和导航用「最短文案」做底稿，别按中文长度定宽。
- 泰语、越南语：行高留出 15% 余量，字体选带完整变音支持的。

## 二、本地化文案：机翻会在这四个地方出事

翻译工具能处理「句子」，处理不了「交易细节」。多语言落地页上，真正会出事的是这四类文案：

1. **货币与数字**：小数点还是逗号、货币符号放前面还是后面、千分位怎么隔。一个错位，用户会以为价格差十倍。
2. **日期与地址**：日/月顺序、地址从大到小还是从小到大、邮编位置。填单页最容易在这里劝退。
3. **称呼与语气**：英语的 Mr/Mrs、西语的 tú/usted、阿语的敬语层级。机翻经常把「你」翻成冒犯的版本。
4. **支付与合规文案**：货到付款、电子钱包、退款政策、免责声明。这些必须由懂当地规则的人过一遍，不能机翻。

判断标准：**把填单流程完整走一遍，用目标语言读，读到任何一句让你犹豫「本地人会这么说吗」，就改。**

## 三、追踪与分流：语言一换，数据最容易断

这是最容易被忽略、代价最大的一关。语言切换常见三种实现，每一种都可能让数据断掉：

- **子路径**（`/en/`、`/ar/`）：最容易做对，但要确保 UTM 参数在切换语言时不丢。
- **子域名**（`en.example.com`）：跨子域时 Cookie 和统计要单独配置，否则同一个用户被算成两个人。
- **自动跳转**（按浏览器语言）：最容易丢参数，也最容易让广告审核和用户看到不同版本。

判断标准：**从广告链接点进来，切一次语言，看 URL 里的 UTM、短链参数、页面上的像素事件是否还在。**

不合格怎么改：

- 语言切换只改路径，保留全部查询参数。
- 每个语言版本都装同一套事件，事件名保持一致，别一个版本叫 `Lead`、另一个叫 `lead_form`。
- 分流短链按国家/语言配置目标，别让阿语用户落到英语客服。

## 什么情况下别做多语言

不是所有市场都值得单独做一版。满足下面任意两条再开工：

- 这个市场的广告花费已经连续 2 周超过其他市场；
- 有能读该语言的客服或合作方；
- 客单价撑得住本地化成本（翻译 + 排版 + 测试）。

只满足一条，先用英语版 + 机器翻译的落地页试水，别急着铺 69 种语言。

## 上线前自检

- [ ] 每个语言版本逐一切换，按钮、价格、表单标签没有错位
- [ ] 阿拉伯语/希伯来语页面整体 RTL，图标镜像
- [ ] 填单流程用目标语言完整走一遍，四个人名/地址/电话格式都能填
- [ ] 从广告链接进入，切语言后 UTM 参数不丢
- [ ] 每个语言版本的事件名一致，后台能按语言拆开看
- [ ] 分流短链按国家/语言配置了正确的接待

## 常见问题

**69 种语言都要做吗？**
不用。先做 3 个：英语 + 花费最高的市场 + 客单价最高的市场。剩下的等数据说话。

**机器翻译能不能直接用？**
落地页的标题和卖点可以机翻后人工改；价格、日期、地址、退款和免责声明必须人工过，这四类机翻出错概率最高。

**多语言会不会拖慢页面？**
静态页面按语言拆开生成、不要运行时翻译，加载速度基本不受影响；运行时翻译插件才是拖慢的主因。
