# 互动问答漏斗（Quiz）与私域客服进粉归因规范

这份文档汇总 `quiz-wheel-funnel-demos`（R9）与 `scrm-webhook-attribution-kit`（R10）两个开源仓库的核心协议：**如何通过前端多步互动问答把冷流量分层，再通过对话首句 `RefCode` 与签名 Webhook 把「真实入站开口」精准归因回广告计划**。

## 1. 全链路数据流：从互动问答到客服真实开口

```text
[广告点击 ?utm_source=tiktok&ttclid=TT_99]
        │
        ▼
[R9 互动问答漏斗 (Quiz / StepFlow)]
  用户点选 3 道选择题 → 计算分值 (score) 与人群标签 (tags)
  自动匹配对应接待组 URL，并生成带答案摘要与归因短码的预填首句：
  "Hi, I'd like the custom plan [Quiz: Goal=Whitening | Skin=Sensitive] [ref:LP05_TT_9A2C]"
        │
        ▼
[WhatsApp / Telegram / LINE 客户端唤起]
  访客按下发送键 → 产生「真实入站开口（Real Inbound Conversation）」
        │
        ▼
[R10 客服端解析与签名回传 (scrm-webhook-attribution-kit)]
  1. parseInboundRefCode() 提取出 ref_code = "LP05_TT_9A2C"
  2. signWebhookPayload() 生成带时间戳防重放的 HMAC-SHA256 签名
  3. 归因端 verifyWebhookSignature() 验签 + 按 (channel + contact_uid) 幂等去重
  4. 触发真实开口转化上报
```

## 2. 互动转盘（PrizeWheel）上线门禁 3 条硬规则

1. **非空奖品必绑 CTA**：所有权重大于 0 的中奖扇区，必须配置有效的下一步承接链接（客服链接或留资表单），严禁出现「抽中了但没有兑换入口」的死胡同。
2. **同设备 `localStorage` 幂等锁**：同一访客开奖一次后，扇区索引、旋转角度与本地兑换码立即持久化；刷新页面直接恢复已中奖态，防止无限刷转盘。
3. **内置浏览器跳出兜底**：检测到 `FBAN` / `FBAV` / `Instagram` / `BytedanceWebview` 等内置浏览器时，Android 端提供 `intent://` 唤起系统浏览器辅助，并始终保留原链接兜底。

## 3. 客服批量回访「未知状态绝不自动重发」规范

| 发送回执状态 | 状态机流转 | 是否允许自动重试 | 原因 |
|---|---|---|---|
| `confirmed` | `SENT` | — | 已明确送达，等待随机抖动间隔（8–15s）后发下一条 |
| `failed_before_send` | `FAILED` | ✅ 允许稍后重试 | 发送前即报错（如本地断网），消息确定未发出 |
| `unknown`（超时/未确认） | **`PENDING_MANUAL_REVIEW`** | **❌ 严禁自动重发** | 极可能已发出但回包丢失；自动重发会导致同一客户连收 3 条相同话术 |
